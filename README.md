2026-11-03已將正式程式、可攜測試與雲端部署管道同步至GitHub main，PR #2已合併。
Google Cloud網頁無法在GPT雲端瀏覽器開啟時，可改由GitHub Actions執行查核與核准式部署，不依賴原電腦或Cloud Shell。

## 雲端接手入口

1. 新GPT對話先讀本README、DEPLOYMENT_SETUP.md與UI_GUIDE.md，並以GitHub main作為程式來源。
2. 先用 `ops/cloud-request.json` 的check模式查核正式狀態，讀取Actions的cloud工作安全摘要。不要把本節歷史版本當永遠不變的目前版本。
3. 功能修改用分支與PR，先測試並取得本次變更核准後合併。只合併程式不會觸發此工作流程部署。
4. 要部署時，取得使用者對本次變更與用量費用的同意，再更新main的請求檔：mode=deploy、source_sha=已合併且核准的40碼commit、expected_revision=最新查核所見的正式版本，request_id用新的識別文字。
5. Actions會先跑測試，再等待production環境的核准；核准通過才建置映像與部署。可從手機GitHub頁面核准，不必輸入終端指令。建立管道的同意不是對所有未來變更的永久部署授權。
6. 每次完成部署後，把請求檔改回check模式，避免重送舊部署請求。也可在GitHub的工作流程頁手動執行。

目前GPT GitHub連接曾回覆寫入403；不要誤認讀取成功就代表能寫入。可使用已登入的GitHub雲端瀏覽器編輯／提交檔案；新瀏覽器的登入與舊電腦不會自動共用，不要把密碼或Token貼到對話。

## 測試

Python 3.11 或 3.12：`python -X utf8 run_offline_tests.py`。
這組 132 項測試不需正式憑證，不會連正式資料庫、Google Sheets 或 LINE。
官方 LINE SDK 序列化另以 `python -X utf8 -m unittest -q test_line_buttons.py` 驗證，所有發送介面皆 mock。

PostgreSQL 整合測試須在隔離 Linux 測試環境執行 `python run_isolated_tests.py`。
需要 PostgreSQL 16 工具及 psycopg2；執行器只建立 `/tmp/group-credit-pg-*` Unix socket 的拋棄式資料庫，測試拒絕正式連線字串。
不能直接把 test_postgres.py 指向正式資料庫。

禁止直接 import app.py 當離線檢查：啟動程式可能讀取真實服務。
requirements.txt 保留正式版本原內容；尚未建立相依套件版本鎖檔，重建映像不保證套件版本與舊映像完全相同。

## 客人測試群（2026-11-04）
- 管理員在指定的新群傳 `/自助綁定 測試`，建立獨立群組帳戶；預設關閉、欠款0、上限未設定。
- 沿用軒的群組共用額度與核准成員規則：`/欠款上限 金額`、`/自助核准 LINE_ID`，最後 `/開放自助`。沒有軒帳戶可供複製的額度時不得猜測，也不會自動核准其他人。
- `/test100*1` 從現存 test100 商品取一張；測試原價定義為1000，9.05折單價905。商品原名「測試商品100」不代表本次售價基準。
- 測試帳戶僅可拿 test100，軒帳戶僅可拿既有MY商品；後端即使是管理員也不能繞過商品隔離。庫存查詢依帳戶過濾。
- 測試訂單與欠款仍保留於資料庫，標示測試客戶；不寫入正式銷售試算表或商品銷售欄。撤回同樣不碰正式試算表，仍需原有兩步文字確認。
- 沒有自動辨識LINE群組名稱，必須由管理員在正確群組綁定。改群名不會改變帳戶模式。不新增、清空或重置任何測試序號。

## 群組計算機（2026-11-04）
僅在已綁定自助帳戶的群組啟用；`GROUP_SELF_SERVICE_ENABLED` 仍維持既有總開關。一般聊天保持無回應。
- 核准成員或主管理員傳 `+0`：讀取本群目前欠款與剩餘額度，回覆無按鈕Flex小卡，不寫入帳務事件。
- 僅 `is_admin` 既有主管理員可手動記帳；`authorized_users`、群組核准拿卡成員不會因此獲得調帳權限。
- 沿用參考計算機正負方向：`+1000` 是收到1000元、減少欠款；`-1000*0.905` 是增加905元欠款。亦可 `/計算 -1000*0.905 #補帳`；備註最多60字。
- 支援數字、小數、加減乘除及小括號，Decimal最後四捨五入至分；拒絕eval、函式、次方、整除、指數、除以0及超長算式。每個手動記帳事件保存算式及備註。
- 與自動拿卡共用同一群組帳戶鎖、訊息去重與帳款稽核。手動記帳不發卡、不扣庫存、不寫銷售試算表；測試帳與軒帳仍分開。收款先結清欠款，超過部分保留預付款；拿卡先扣預付款，不足部分才列欠款。
- 管理員可補記超過額度的舊欠款，後續自助拿卡仍被額度攔截。拿卡已自動增加欠款，勿另外輸入同筆負數重複加帳。
- 發送逾時不重送、不反向調帳；同一訊息重送不會重複調帳，可再傳+0查帳。小卡本機建構錯誤才在發送前降回文字。

## 記帳防護與更正（2026-11-04）
計算機同一群、同一管理員在120秒內輸入相同欠款變動，先建立待確認紀錄，不調帳；回覆 `/確認記帳 CP...` 或 `/取消記帳 CP...`，5分鐘有效。重複記帳由原管理員確認，帳戶列鎖與固定確認事件識別碼保證並發、重送均只入帳一次。+0不新增事件。
主管理員可 `/記帳紀錄` 查最近10筆（拿卡、手動帳、收款、撤回、更正），不顯示卡密或人員ID；手動記帳小卡附AC編號。
`/更正記帳 記帳編號 原因`（或 `/撤銷記帳 ...`）先顯示文字確認，再增加一筆相反金額的沖回紀錄，原帳保留並標示已更正。支援原計算機與增加欠款/登記收款/減少欠款的手動帳；禁止更正拿卡銷售與再次更正沖回紀錄。確認時重驗帳戶餘額與來源紀錄，防止重複沖回；退款可回存為預付款。更正可由同群另一位主管理員接手；發卡撤回的管理員接手權限保持既有行為。
待確認事件不列入帳目清單；所有新流程只操作群組帳務，不操作庫存或銷售試算表。正式拿卡仍同步原銷售明細，測試群仍略過正式試算表。
`lock_inventory_summary.sql` 為本次明確核准的匿名存取縮減，僅撤除 inventory_summary 的 PUBLIC/anon SELECT；不更動視圖內容、卡片、訂單、登入角色或服務帳號。由維護者透過已授權Supabase操作套用，Cloud Run發佈流程仍不自動執行SQL。

## 客人群管理員撤回捷徑（2026-11-04）
在已綁定自助帳戶的客人群，主管理員可輸入 `/撤回`，在帳戶鎖內選取最近一筆實際帳務異動；若是手動記帳，建立既有文字確認申請，確認後沖回，原帳與稽核保留。可由另一位管理員接手確認。
不會跳過較新的拿卡、發卡撤回或更正紀錄去撤回更早的手動帳；會提示使用對應指令。待確認紀錄及+0查帳不算帳務異動。
亦可 `/撤回 記帳編號 原因` 精確指定手動帳；不回收卡片。未綁定客人的管理群仍沿用原本一般 `/撤回` 邏輯，正式拿卡仍使用 `/自助撤回 訂單編號` 及未使用確認。

## 預付款帳戶（已佈署）
管理員輸入 `+20000` 表示實收20000元。若原欠14525元，結果為欠款0元、預付款5475元；再拿905元卡，預付款剩4570元。`+0` 只查帳。負數算式仍表示加帳，優先扣預付款。
小卡分開顯示欠款和預付款，兩者均為正數。「可拿卡總額」為預付款加剩餘賒帳額度；核准成員、開放狀態、額度上限及商品限制仍須符合。收款與退款均留稽核，已付款訂單確認未使用回收後，退款回存預付款。手動收款不產生銷售明細。
帳戶原 `debt` 欄位改存淨額：正值欠款、負值預付。既有資料無須搬移或歸零；`enable_group_prepay.sql` 僅調整範圍約束，必須與相容程式協調上線，不能單獨套用後繼續使用舊程式。正式資料未因開發測試變更。
